## 設計規則

本章定義跨函式庫、作業系統介面與圖形 API 保持穩定的設計規則。每種執行機制都必須維持相同的責任歸屬、提交邊界、完成條件與資源所有權。

本章規則不得因實作調整而擅自更動。實作需求若必須變更設計規則，應先說明變更原因與影響，並經過審查後才能修改。

### 執行角色與責任

系統由一個協調角色與三類任務執行角色組成。下表只界定每項工作的責任歸屬與交付結果；執行時必須維持的非同步與平行關係由下一節定義。

| 角色 | 唯一責任 | 輸出 |
| --- | --- | --- |
| 主執行緒 | 序列化全域控制狀態，依事件決定狀態轉移並建立工作描述或狀態授權 | 工作描述、狀態授權 |
| CPU 任務執行器 | 執行 CPU 密集的資料處理工作 | 完成結果與資源參照 |
| 儲存任務執行器 | 執行目錄與檔案系統工作 | 圖片標頭、檔案內容或圖片檔案清單 |
| 圖形任務執行器 | 執行資源傳輸、繪製與畫面提交工作 | 傳輸或畫面結果 |

新增工作時，依工作語意與狀態所有權選擇上述角色。每項資源由唯一角色負責建立、回收與重用；任務執行器只取得工作期間有效的使用授權。資源參照只用於定位資源，不參與資源生命週期；工作完成或取消後交回使用授權，資源才能回收或重用。

### 非同步交接與平行執行

#### 非同步交接

每項工作依下列生命週期跨越主執行緒與任務執行器：

- **提交**：主執行緒建立工作描述與資源使用授權，將工作交給對應執行器後結束本次控制步驟。
- **獨立執行**：提交與完成之間，主執行緒與任務執行器在各自具有可執行工作時同時推進。
- **完成**：任務執行器產生完成事件；主執行緒收到事件後接收結果、收回資源使用授權並轉移全域控制狀態。

#### Task parallelism

> 兩個以上的 task 在執行期間彼此獨立，並在同一時刻同時執行各自的工作本體。

資源授權界定 task 在執行期間可持續使用，且不與其他同時執行 task 衝突的資源。

- **派發前**：task 所需的輸入資料已就緒，並取得資源授權。
- **執行期間**：獨立推進並持續持有資源授權，不因資源搶占而分時、阻塞或等待。
- **取消**：控制狀態變更可以發出取消要求；task 停止存取後才交回資源。
- **完成時**：以完成事件同時交回結果與資源。

#### 管線中的套用方式

**非同步交接**：每張圖片依序通過儲存、CPU 與圖形階段。主執行緒提交目前階段後返回事件處理；目前階段的完成事件提供下一階段所需的輸入，輸入與資源均就緒後再派發下一階段。

**平行處理**：不同圖片分別位於儲存、CPU 與圖形階段，各階段的 task 在資源授權允許時同時執行。各任務執行器執行已提交 task 的同時，主執行緒處理已就緒事件；沒有已就緒事件時進入中央事件等待。

**執行緒數量**：應用程式執行緒固定由一個主執行緒與固定數量的 CPU Workers 組成。主執行緒負責協調；CPU Workers 只執行會隨資料量成長的 CPU 密集 task。儲存任務執行器與圖形任務執行器不建立其他應用程式執行緒。

各角色採用的具體執行資源、提交介面、資源種類與容量計算方式由實作層對應。

### 標頭優先的資源準備原則

首次接觸圖片時，儲存管線必須優先產生足以決定後續資源配置的標頭資訊。標頭資訊就緒後即可驗證格式、決定輸出尺寸與配置、保留記憶體額度並準備輸出資源；其餘檔案內容可在同一期間繼續讀取。

後續讀取同一張圖片且已保存的標頭資訊仍有效時，該資訊直接啟動資源準備，儲存任務執行器只需提供本次 CPU 工作所需的完整內容。這項原則由以下完成條件定義：

- 「標頭就緒」表示後續資源形狀已可決定。
- 「內容就緒」表示 CPU 工作所需的輸入內容已完整。
- 「資源就緒」表示輸出資源與記憶體額度已準備完成。
- 三項條件同時成立後，工作才具備進入 CPU 任務執行器的資格。

首次讀取時，標頭資訊與其餘檔案內容以非同步工作分成兩條可平行推進的邏輯路徑。標頭路徑推動格式驗證與輸出資源準備，內容路徑取得 CPU 工作所需的完整輸入。兩條路徑的完成條件最後匯合，決定工作何時可以派發：

```text
圖片需求
├─優先取得標頭資訊─▶ 標頭就緒 ─▶ 驗證與準備輸出資源 ─▶ 資源就緒
└─取得其餘檔案內容──────────────────────────────────▶ 內容就緒

標頭就緒 ＋ 內容就緒 ＋ 資源就緒 ─▶ 可派發 CPU 工作
```

儲存介面可以依平台能力選擇請求數量、資料切割、對齊方式與完成通知機制。每種實作都必須保留上述三項完成條件，並維持資源準備與其餘內容讀取的重疊關係。

### 單張圖片的處理時序

```text
主執行緒          儲存任務執行器       CPU 任務執行器       圖形任務執行器
    │                    │                    │                    │
    │─非同步提交讀取────▶│                    │                    │
    │◀─標頭就緒事件──────│                    │                    │
    │─更新資源需求並推進資源準備              │                    │
    │◀─內容就緒事件──────│                    │                    │
    │─非同步派發 CPU 工作────────────────────▶│                    │
    │◀─CPU 工作完成事件───────────────────────│                    │
    │─非同步提交資源傳輸─────────────────────────────────────────▶│
    │◀─資源傳輸完成事件───────────────────────────────────────────│
    │─建立呈現授權並非同步提交繪製───────────────────────────────▶│
    │◀─畫面完成或呈現額度事件─────────────────────────────────────│
```

圖中的垂直順序只表示同一張圖片的資料相依性；箭頭沿用前節定義的非同步交接。具體 API 與資料結構由實作層選擇。

### 主執行緒的控制邊界

主執行緒以維持低控制延遲為首要目標，及時完成狀態協調與工作交接；必須由主執行緒同步完成的操作維持在必要範圍內。

## 實作對應

前章的設計規則是責任與完成條件的依據；本章將程式元件對應到各項設計角色與交接契約。

### 關係種類

```text
事件→ 外部輸入或非同步完成通知，經事件分派器送至固定事件處理流程
讀取→ 使用狀態或資料並保持原值
寫入→ 建立或取代狀態或資料
讀寫→ 讀取後修改同一狀態或資源
擁有→ 對指定狀態、資源生命週期或共享通道承擔唯一管理責任
計算→ 產生本次同步呼叫使用的暫時選擇或順序，並保持持久狀態原值
判斷→ 依已讀取資料選擇控制分支，並保持持久狀態原值
呼叫→ 事件處理流程立即執行事件專用流程或共用流程
命令→ 呼叫固定成本的控制 API，並在同一個控制步驟內返回
派發→ 非同步將 CPU 工作描述放入工作佇列；Worker 完成後產生完成事件
提交→ 非同步將儲存要求或圖形命令交給外部執行資源；完成後產生系統事件
```

事件參數攜帶事件來源資料；其餘判斷所需的全域控制狀態與工作資源由應用程式責任邊界提供，並由主執行緒依序修改。各任務執行器自行管理其內部狀態。

### 啟動流程

主執行緒先建立儲存任務執行器、完成通知與固定容量的 Slot 狀態儲存區，並設定執行優先權。一般圖片瀏覽工作階段接著為首圖建立暫時圖片檔案清單與資源保留，立即提交首圖讀取，再提交首圖所在目錄的非同步列舉；主執行緒隨後建立視窗與 CPU 任務執行器。

```text
主執行緒                 儲存任務執行器          CPU 任務執行器          圖形任務執行器
    │                          │                       │                       │
    ├─建立儲存任務執行器與完成通知                     │                       │
    ├─建立固定容量的 Slot 狀態儲存區                    │                       │
    ├─設定主執行緒執行優先權                           │                       │
    ├─建立首圖暫時圖片檔案清單與資源保留               │                       │
    ├─提交標頭優先的首圖讀取─────────────────────────▶│                       │
    ├─提交首圖所在目錄的非同步列舉───────────────────▶│                       │
    ├─建立未顯示的視窗與 CPU 任務執行器                │                       │
    │                          │                       │                       │
    ├─接收並處理已就緒的儲存完成事件                  │                       │
    │  ├─標頭就緒：驗證格式並準備首圖解碼輸出資源     │                       │
    │  ├─內容就緒：首圖完整輸入可供解碼               │                       │
    │  └─目錄列舉完成：建立完整圖片檔案清單與資源保留 │                       │
    ├─每次處理後判斷首圖三項條件                      │                       │
    │  └─條件就緒時立即派發 PNG 解碼────────────────▶│                       │
    ├─每次處理後判斷首圖內容與圖片檔案清單            │                       │
    │  └─兩者就緒時一次提交其餘全部可執行的檔案讀取─▶│                       │
    ├─同步初始化圖形裝置      │                       │                       │
    │                          ├─推進已提交的檔案讀取   ├─執行已派發的 PNG 解碼 │
    │                          │                       │                       │
    ├─接收圖形初始化期間完成的儲存結果                │                       │
    ├─後續 PNG 解碼直接使用 staging texture─────────▶│                       │
    ├─完成其餘圖形資源初始化                                                     │
    ├─顯示視窗                 │                       │                       │
    └─進入主事件迴圈           │                       │                       │
       ├─首圖解碼成功時將 CPU 結果一次複製至 staging texture                  │
       ├─提交資源傳輸───────────────────────────────────────────────────────▶│
       └─資源傳輸完成後繪製並提交畫面───────────────────────────────────────▶│
```

首圖解碼只取決於「標頭就緒、內容就緒、資源就緒」，不等待目錄列舉完成。其餘檔案讀取則在首圖內容與完整圖片檔案清單都就緒後一次提交；主執行緒隨即同步初始化圖形裝置，使首圖解碼、其餘檔案讀取與圖形初始化平行推進。

圖形裝置初始化前派發的首圖使用暫時 CPU 解碼記憶體；裝置完成後，成功的解碼結果只複製一次至解碼 staging texture。其後圖片直接解碼至 staging texture；可供繪製的 GPU Texture 在解碼完成並提交資源傳輸時建立或重用。

### 共用流程

圖中未加前綴的狀態與資源都位於應用程式責任邊界內。

#### 推進管線

```text
[共用流程] 推進管線
│
├─呼叫→ 重新計算緩衝需求
├─呼叫→ 回收範圍外工作與 slots
├─呼叫→ 批次填充工作佇列
├─呼叫→ 批次提交可執行的檔案讀取
├─呼叫→ 批次提交可執行的 GPU 上傳
├─呼叫→ 嘗試提交下一張畫面
└─判斷→ 畫面提交改變控制狀態時，依更新後的狀態重新推進
```

所有需要推進管線的事件處理流程都在完成事件專用的狀態更新後呼叫本流程。共用流程依同一順序重新計算需求、回收不再需要的工作與資源、提交已滿足條件的工作，並在畫面提交改變目前呈現位置後立即處理新的需求範圍。

#### 重新計算緩衝需求

```text
[共用流程] 重新計算緩衝需求
│
├─讀取→ 圖片索引範圍
├─讀取→ 按住方向
├─讀取→ 最後有效導航方向
├─讀取→ 待完成短按承諾
├─讀取→ 長按 repeat 暫定終點
├─讀取→ 目前呈現索引
│
├─寫入→ 必須依序呈現範圍
├─寫入→ 解碼預取範圍
└─寫入→ GPU 預取範圍
```

輸入狀態、索引邊界及目前呈現位置決定導航授權與緩衝範圍；解碼結果決定圖片進入後續管線的時機。

#### 回收範圍外工作與 slots

```text
[共用流程] 回收範圍外工作與 slots
│
├─讀取→ 必須依序呈現範圍
├─讀取→ 解碼預取範圍
├─讀取→ GPU 預取範圍
├─讀寫→ 每張圖片的需求狀態與關聯 Slot ID
├─讀寫→ 工作佇列的生產端與工作取消旗標
├─讀寫→ 壓縮 PNG slot 狀態與可分配索引
├─讀寫→ 解碼 staging texture slot 狀態與可分配索引
├─讀寫→ GPU Texture slot 狀態與可分配索引
├─讀寫→ 可呈現 GPU 圖片索引
├─讀寫→ staging 與 GPU 記憶體使用量
│
├─判斷→ 已要求且尚未取得 slot 的索引離開需求範圍
│   └─寫入→ 需求狀態為範圍外
├─判斷→ 壓縮 slot 正在接收檔案資料且索引已離開需求範圍
│   ├─寫入→ 壓縮 slot 為等待目前工作結束後回收
│   └─命令→ CancelIoEx
├─判斷→ 仍在工作佇列且索引已離開需求範圍
│   └─寫入→ 以工作項目的原子旗標取消；只有尚未被 Worker 取得時立即釋放資源
├─判斷→ Worker 已取出且索引已離開需求範圍
│   └─寫入→ 完成後可直接釋放
├─判斷→ 解碼 staging texture 位於保留範圍外且未被 Worker 或 GPU 使用
│   └─寫入→ staging slot 為可分配並加入可分配索引
└─判斷→ 可呈現 GPU 圖片位於保留範圍外且索引與目前畫面相異
    ├─寫入→ 從可呈現 GPU 圖片索引移除圖片
    └─寫入→ 對應 GPU Texture slot 等待先前繪製完成後設為可分配並加入可分配索引
```

Slot 狀態儲存區在整個工作階段維持固定容量、Slot ID 範圍與各 Slot ID 的狀態位置。這些固定項目界定可同時保留的名額與資源身分；實體資源按需求與使用授權關聯至 Slot ID，並在授權交回後重用或解除。回收時解除圖片與 Slot ID 的關聯並更新 slot 狀態。可分配索引專門提供可用 Slot ID；工作提交、完成處理與狀態轉換都直接攜帶 Slot ID，資源參照不延長實體資源的生命週期。呈現時透過可呈現 GPU 圖片索引直接取得 GPU Texture Slot ID。

#### 批次提交可執行的檔案讀取

```text
[共用流程] 批次提交可執行的檔案讀取
│
├─讀取→ 必須依序呈現範圍
├─讀取→ 解碼預取範圍
├─讀取→ 圖片檔案清單
├─讀取→ 每張圖片的需求狀態與關聯 Slot ID
├─讀寫→ 壓縮 PNG slot 狀態與可分配索引
├─讀取→ 壓縮資料記憶體使用量
├─讀取→ 預估解碼輸出保留額度
├─讀取→ staging 記憶體額度
│
├─計算→ 範圍內已要求且尚未關聯任何 slot 的圖片
├─計算→ 必須呈現的相鄰圖片優先，其次才是預取圖片
├─判斷→ 對每個目前可容納的圖片
│   ├─寫入→ 取得可分配的壓縮 slot 並設為正在接收檔案資料
│   ├─寫入→ 保留預估解碼輸出額度
│   ├─寫入→ 圖片關聯壓縮 Slot ID
│   ├─判斷→ 標頭資訊狀態
│   │   ├─尚未取得 ─▶ 建立「標頭就緒」與「內容就緒」兩條邏輯路徑
│   │   └─已快取 ───▶ 直接沿用標頭資訊並建立「內容就緒」路徑
│   └─提交→ 符合標頭優先原則的 Windows 非同步檔案 I/O 工作描述
└─判斷→ 待讀需求已全部提交，或下一筆會超過記憶體或 slot 數量上限時結束
```

首圖內容就緒前，本流程只提交首圖讀取。此條件解除後，每次執行本流程都一次提交全部已取得壓縮資料資源保留且目前可執行的讀取；提交集合由需求範圍、記憶體上限與壓縮 slot 數量上限共同決定。每張圖片的讀取工作描述都必須遵守 [標頭優先的資源準備原則](#標頭優先的資源準備原則)。任何釋放 slot 或記憶體額度的事件都會透過推進管線重新執行本流程。

#### 批次填充工作佇列

```text
[共用流程] 批次填充工作佇列
│
├─讀取→ 必須依序呈現範圍
├─讀取→ 解碼預取範圍
├─讀取→ 每張圖片的需求狀態與關聯 Slot ID
├─讀寫→ 壓縮 PNG slot 狀態
├─讀寫→ 解碼 staging texture slot 狀態與可分配索引
├─讀寫→ 工作佇列的生產端
│
├─計算→ 壓縮資料可用且仍需要解碼的圖片
├─計算→ 必須呈現的相鄰圖片優先，其次才是預取圖片
├─判斷→ 對每個壓縮內容與解碼輸出資源都已就緒的圖片
│   ├─命令→ 準備解碼輸出資源的可寫入範圍
│   ├─寫入→ 壓縮 slot 為解碼器正在讀取
│   ├─寫入→ 圖片關聯解碼 staging texture Slot ID
│   └─寫入→ 工作佇列工作
│       ├─壓縮 PNG Slot ID
│       └─解碼 staging texture Slot ID
└─判斷→ 可解碼圖片已全部派發、staging texture 全部使用中或工作佇列已達配置容量時結束
```

解碼輸出資源在標頭就緒後進入已準備狀態。圖形裝置完成前，首圖的解碼輸出資源是已由標頭處理流程準備的暫時 CPU 解碼記憶體；圖形裝置完成後，尚未派發的工作改用解碼 staging texture。標頭資訊已保存的重新載入也經過相同的資源保留與狀態流程。若額度被較低優先且尚未交由 Worker 或 GPU 的資源佔滿，先回收其中優先度最低者，再派發下一張必須呈現的圖片。所有輸入、輸出與資源保留均已就緒的工作會一次派入佇列；Worker 數與名額不在啟動期節流。

#### 批次提交可執行的 GPU 上傳

```text
[共用流程] 批次提交可執行的 GPU 上傳
│
├─讀取→ 必須依序呈現範圍
├─讀取→ GPU 預取範圍
├─讀取→ 每張圖片的需求狀態與關聯 staging Slot ID
├─讀取→ 可呈現 GPU 圖片索引
├─讀寫→ 解碼 staging texture slot 狀態
├─讀寫→ GPU Texture slot 狀態與可分配索引
├─讀寫→ GPU 記憶體使用量
├─讀寫→ GPU 上傳工作
│
├─計算→ 關聯已解碼 staging slot，且不在可呈現 GPU 圖片索引或 GPU 上傳工作中的圖片
├─計算→ 下一張必須呈現的圖片優先，其次依距離排序
├─判斷→ 對每個目前可提交的圖片
│   ├─寫入→ 取得可分配的 GPU Texture slot 並設為 GPU 正在寫入
│   ├─寫入→ GPU 上傳工作
│   │   ├─圖片索引
│   │   ├─解碼 staging texture Slot ID
│   │   ├─GPU Texture Slot ID
│   │   └─GPU fence 完成值
│   ├─提交→ 建立 GPU Texture，內容由本次資源傳輸寫入
│   ├─提交→ 從 staging texture 複製原始圖片範圍至 GPU Texture
│   └─寫入→ staging slot 為 GPU 正在讀取
└─判斷→ 待上傳圖片已全部提交、GPU 記憶體或 slot 數量上限或提交容量已用完時結束
```

GPU Texture 的內容由資源傳輸寫入，傳輸完成後進入可供繪製狀態。staging texture 在 fence 完成前持續作為非同步複製來源。

#### 嘗試提交下一張畫面

```text
[共用流程] 嘗試提交下一張畫面
│
├─讀取→ Frame 提交額度
├─讀取→ 目前呈現索引
├─讀取→ 待完成呈現授權
├─讀取→ 可呈現 GPU 圖片索引
├─讀取→ 索引直接取得的 GPU Texture Slot ID 與 slot 狀態
│
├─判斷→ 呈現授權序列為空時保持目前畫面
├─判斷→ 下一個相鄰索引仍在 GPU 上傳前階段時保持目前畫面並等待該索引
├─判斷→ Frame 提交額度處於等待狀態時等待後續額度事件
└─判斷→ 呈現授權、相鄰 GPU 圖片與 Frame 額度全部可用
    ├─提交→ Direct2D 使用該 GPU Texture Slot ID 高品質繪製至實體像素 back buffer
    ├─提交→ DXGI SwapChain Present
    ├─寫入→ 消耗一份 Frame 提交額度
    ├─寫入→ 目前呈現索引
    └─寫入→ 完成對應呈現授權
```

每份 Frame 提交額度最多推進一張。重新繪製同一張圖片會保持呈現授權與目前呈現索引原值。成功推進至相鄰圖片後，更新後的控制狀態交回推進管線。

### 事件處理

#### 開啟圖片事件

```text
[事件處理流程] 開啟圖片
│
├─呼叫→ [事件專用] 建立瀏覽工作階段
│   ├─讀取→ 事件攜帶的起始圖片路徑
│   ├─讀取→ 起始圖片可用的檔案大小資訊
│   ├─寫入→ 只含起始圖片的暫時圖片檔案清單與管線狀態
│   ├─寫入→ 暫時呈現索引
```

#### 目錄 I/O 完成事件

```text
[事件處理流程] 目錄 I/O 完成
│
├─讀取→ 原生非同步目錄列舉的完成資料
├─寫入→ 解析每個 PNG 檔案的位置與大小
├─判斷→ 尚有項目時提交下一批原生非同步目錄查詢
├─寫入→ 完成時排序圖片檔案清單並定位首圖正式索引
├─寫入→ 將首圖既有 I/O 與 slot 關聯移至正式索引
├─寫入→ 初始化其餘圖片的管線狀態與導航範圍
├─寫入→ 更新尚在佇列中的首圖工作與 slot 內正式圖片索引
└─呼叫→ 推進管線
```

此處理流程只在 Windows I/O 完成事件到達後執行，並由事件迴圈統一等待通知。首圖 I/O 完成不必等待完整圖片檔案清單；合併時沿用首圖已配置的壓縮 slot、真實檔案大小及可能已排入佇列的工作，並以 slot 保存的正式圖片索引接收 Worker 結果。

輸入事件決定導航授權；解碼與 GPU 結果決定授權進入可呈現狀態的時機。

#### 檔案 I/O 完成事件


解碼輸出資源的配置只取決於標頭提供的尺寸與資源保留，與其餘檔案內容是否完成無關。圖形裝置初始化期間，首圖使用標頭處理流程準備的暫時 CPU 解碼記憶體；圖形裝置完成後，該次結果複製至解碼 staging texture，後續圖片直接使用 staging texture。可供繪製的 GPU Texture 在解碼完成並提交資源傳輸時建立或重用。

```text
[事件處理流程] 檔案 I/O 完成
│
├─呼叫→ [事件專用] 處理檔案 I/O 完成結果

│   ├─讀寫→ 每張圖片的需求狀態與關聯壓縮 Slot ID

│   ├─判斷→ 成功且仍需要
│   │   └─寫入→ 壓縮 slot 為可供解碼
│   ├─判斷→ 成功且索引已離開需求範圍
│   │   └─寫入→ 壓縮 slot 為可分配、加入可分配索引，並釋放預估輸出保留額度
│   └─判斷→ 失敗或取消完成
│       └─寫入→ 壓縮 slot 為可分配、加入可分配索引，並釋放預估輸出保留額度

```

成功且保留的壓縮資料持續計入記憶體用量。本次處理釋放額度時，既有等待需求會依新的可用額度進入批次提交判斷。

#### Worker 工作完成事件

```text
[事件處理流程] Worker 工作完成
│
├─呼叫→ [事件專用] 處理完成佇列中的已就緒結果
│   ├─讀取→ Worker 工作完成結果
│   ├─讀寫→ 每張圖片的需求狀態與關聯 Slot ID
│   ├─讀寫→ 壓縮 PNG slot 狀態與可分配索引
│   ├─讀寫→ 解碼 staging texture slot 狀態與可分配索引
│   ├─判斷→ 解碼輸出資源為 staging texture
│   │   └─命令→ 解除 staging texture 映射
│   ├─判斷→ 成功且仍需要
│   │   ├─判斷→ 解碼輸出資源為首圖 CPU 解碼記憶體
│   │   │   └─命令→ 將解碼結果複製至 staging texture
│   │   └─寫入→ staging slot 為已解碼且可供 GPU 複製
│   ├─判斷→ 成功且索引已離開需求範圍
│   │   └─寫入→ staging slot 為可分配並加入可分配索引
│   ├─判斷→ 失敗
│   │   └─寫入→ 需求狀態為失敗並釋放 staging slot
│   └─判斷→ 每個完成結果
│       └─寫入→ 釋放已消耗的壓縮資料
│
└─呼叫→ 推進管線
```

Worker 完成事件在解碼輸出資源為 staging texture 時先解除映射；解碼成功且資源使用授權仍有效時，首圖 CPU 解碼結果才會完成至 staging texture 的唯一一次交接。處理流程隨後轉換 staging slot，並釋放對應的壓縮 slot；更新後的資源狀態由推進管線統一處理。

#### GPU 上傳完成事件

```text
[事件處理流程] GPU 上傳完成
│
├─呼叫→ [事件專用] 處理 GPU 上傳完成結果
│   ├─讀取→ 本次事件提供的 GPU 上傳完成結果
│   ├─讀寫→ GPU 上傳工作
│   ├─讀寫→ GPU Texture slot 狀態與可分配索引
│   ├─讀寫→ 解碼 staging texture slot 狀態與可分配索引
│   ├─讀寫→ 可呈現 GPU 圖片索引
│   ├─判斷→ 成功且圖片仍在 GPU 保留範圍
│   │   ├─寫入→ GPU Texture slot 為可供 Direct2D 繪製
│   │   ├─寫入→ 可呈現 GPU 圖片索引
│   │   │   └─圖片索引 → GPU Texture Slot ID
│   │   └─寫入→ staging slot 為可分配並加入可分配索引
│   ├─判斷→ 成功但圖片已離開 GPU 保留範圍

│   │   └─寫入→ staging slot 為可分配並加入可分配索引

│   └─判斷→ 每個完成結果
```

GPU 完成會釋放複製來源 staging slot，讓等待解碼或等待讀取的既有需求重新進入執行判斷；導航需求由輸入事件建立。

### 任務執行器與外部事件來源

```text
[應用程式任務執行器] Worker
│
├─讀寫→ 工作佇列的消費端與工作取消旗標
├─讀取→ 工作描述指定的輸入資源 Slot ID
├─計算→ 工作描述指定的 CPU 密集階段
├─寫入→ 工作描述指定的輸出資源 Slot ID
├─讀寫→ 完成佇列的生產端
└─事件→ Worker 工作完成 [主事件迴圈]
```

工作佇列只包含 PNG 解碼：輸入為 Windows 非同步檔案 I/O 填入的壓縮 PNG slot，輸出為工作描述指定的解碼輸出 slot。圖形裝置完成前，首圖輸出由暫時 CPU 解碼記憶體承載；其後輸出由已映射的 staging texture 承載。所有 Workers 從同一條工作佇列領取這些 CPU 密集工作。

```text
[外部非同步執行器] Windows 非同步檔案 I/O
│
├─讀取→ 批次提交流程建立的檔案範圍、長度與目的緩衝區
├─寫入→ 壓縮 PNG slot 中對應的檔案內容範圍
├─事件→ 首次讀取的標頭資訊就緒 [主事件迴圈]
└─事件→ 完整內容就緒 [主事件迴圈]
```

Windows 儲存介面的對應方式如下：

| 情境 | 機制 |
| --- | --- |
| 目錄列舉 | `NtQueryDirectoryFileEx` 原生非同步查詢 |
| Windows 11 | I/O Ring 已註冊檔案表與緩衝區表；I/O Ring 不可用時明確失敗 |
| 首次讀取 | I/O Ring 標頭讀取與未被標頭涵蓋的內容範圍同批提交 |
| 標頭資訊已保存 | 沿用既有標頭資訊，並以一筆 I/O Ring 內容讀取提交完整內容 |

首次讀取的標頭範圍至少涵蓋 PNG 解析器判斷輸出資源所需的 24 位元組，並依底層儲存介面的 I/O 最小單位向上對齊。每張圖片固定保留一個內容讀取狀態；標頭範圍未覆蓋的內容由這個讀取一次提交，標頭範圍已覆蓋完整檔案時則由標頭完成同時滿足內容就緒。首圖與後續圖片都依實體對齊粒度擴張傳輸緩衝區，且不改變壓縮資料資源保留數量。標頭與內容的檔案範圍完整覆蓋本次內容且彼此不重疊。這些數值與 API 屬於 Windows 與 PNG 配接層；設計層的要求是「標頭就緒、內容就緒、資源就緒」三項完成條件及其重疊關係。

I/O Ring 的檔案表與緩衝區表都以固定壓縮 PNG Slot ID 作為索引。每批先以 `REGISTER_FILES` 提交完整檔案表；緩衝區表只在 slot 首次配置、擴充或回收造成位址或容量改變時以 `REGISTER_BUFFERS` 更新。其後的讀取使用 `IORING_REF_REGISTERED` 指定表索引與緩衝區位移；註冊與同批後續讀取之間的相依關係，保證讀取在表更新後開始。首圖以 `GetFileSizeEx` 取得大小並完成壓縮 slot 配置後即可註冊，不等待完整圖片檔案清單。後續批次保留仍在 I/O 中的 slot 索引，檔案表以空項目移除不再使用的檔案控制代碼。緩衝區位址或容量改變時，舊緩衝區會保留至新緩衝區表更新完成。檔案控制代碼、註冊表與壓縮 slot 都維持有效至對應完成項目到達；關閉時依序取消待完成 I/O、排空完成項目、關閉 I/O Ring，再釋放延後回收的緩衝區。

驗證報告中的首圖內容完成觀測時間，是主執行緒呼叫 `PopIoRingCompletion` 取得內容讀取完成項目的時間。`IORING_CQE` 不含核心完成時間戳，因此該時間可能晚於儲存工作在核心完成的時間。

```text
[外部非同步執行器] GPU 命令佇列
│
├─讀取→ GPU 上傳工作指定的解碼 staging texture slot
├─寫入→ GPU 正在寫入的 GPU Texture slot
└─事件→ GPU 上傳完成 [主事件迴圈]
```

```text
[外部事件來源] DXGI SwapChain
│
└─事件→ Frame 提交額度可用 [主事件迴圈]
```

工作佇列與完成佇列是主執行緒和 Workers 之間的共享通道。工作項目的原子旗標協調「等待領取、已由 Worker 取得、已取消」；完成佇列由多個 Worker 寫入，主執行緒依完成事件讀取結果。工作只攜帶工作種類與 Slot ID；Slot 狀態儲存區維持固定的名額、Slot ID 範圍與狀態位置，slot 狀態授權單一 Worker 在 CPU 密集工作期間讀寫指定資源。
