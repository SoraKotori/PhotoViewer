## 設計規則

本章定義跨函式庫、作業系統介面與圖形 API 保持穩定的設計規則。每種執行機制都必須維持相同的責任歸屬、提交邊界、完成條件與資源所有權。

### 執行角色與責任

系統由一個協調角色與三類任務執行角色組成。下表只界定每項工作的責任歸屬與交付結果；執行時必須維持的非同步與平行關係由下一節定義。

| 角色 | 唯一責任 | 輸出 |
| --- | --- | --- |
| 主執行緒 | 序列化全域控制狀態，依事件決定狀態轉移並建立工作描述或狀態授權 | 工作描述、狀態授權 |
| CPU 任務執行器 | 執行 CPU 密集的資料處理工作 | 完成結果與資源參照 |
| 儲存任務執行器 | 執行目錄與檔案系統工作 | 標頭、內容或目錄結果 |
| 圖形任務執行器 | 執行資源傳輸、繪製與畫面提交工作 | 傳輸或畫面結果 |

新增工作時，依工作語意與狀態所有權選擇上述角色。成本來源用來核對分工：資料處理時間歸 CPU 任務執行器，儲存延遲歸儲存任務執行器，圖形處理時間歸圖形任務執行器；主執行緒只處理記憶體內的控制狀態。資源由其擁有者維持生命週期，角色之間只傳遞工作描述、完成結果、資源參照與使用授權。

### 非同步交接與平行執行

#### 非同步交接

每項工作依下列生命週期跨越主執行緒與任務執行器：

- **提交**：主執行緒建立工作描述與資源使用授權，將工作交給對應執行器後結束本次控制步驟。
- **獨立執行**：提交與完成之間，主執行緒與任務執行器在各自具有可執行工作時同時推進。
- **完成**：任務執行器產生完成事件；主執行緒收到事件後接收結果、收回資源使用授權並轉移全域控制狀態。

#### Task parallelism

> 兩個以上的 task 在執行期間彼此獨立，並在同一時刻同時執行各自的工作本體。

資源授權界定 task 在執行期間可持續使用，且不與其他同時執行 task 衝突的資源。

- **派發前**：task 所需的輸入資料已就緒，並取得資源授權。
- **執行期間**：獨立推進並持續持有資源授權，不因資源搶占而分時、阻塞或等待。
- **取消**：控制狀態變更可以發出取消要求；task 停止存取後才交回資源。
- **完成時**：以完成事件同時交回結果與資源。

#### 管線中的套用方式

**非同步交接**：每張圖片依序通過儲存、CPU 與圖形階段。主執行緒提交目前階段後返回事件處理；目前階段的完成事件提供下一階段所需的輸入，輸入與資源均就緒後再派發下一階段。

**平行處理**：不同圖片分別位於儲存、CPU 與圖形階段，各階段的 task 在資源授權允許時同時執行。各任務執行器執行已提交 task 的同時，主執行緒處理已就緒事件；沒有已就緒事件時進入中央事件等待。

**執行角色**：應用程式執行緒固定為主執行緒與 CPU Workers；兩者共同使用程序可取得的 CPU 執行資源，但維持不同職責。儲存與圖形工作透過外部任務執行器推進；任何會隨資料量成長的 CPU 處理都建立為 CPU task 交給 Workers。

各角色採用的具體執行資源、提交介面、資源種類與容量計算方式由實作層對應。

### 標頭優先的資源準備原則

首次接觸圖片時，儲存管線必須優先產生足以決定後續資源配置的標頭資訊。標頭資訊就緒後即可驗證格式、決定輸出尺寸與配置、保留記憶體額度並準備輸出資源；其餘檔案內容可在同一期間繼續讀取。

後續讀取同一張圖片且已保存的標頭資訊仍有效時，該資訊直接啟動資源準備，儲存任務執行器只需提供本次 CPU 工作所需的完整內容。這項原則由以下完成條件定義：

- 「標頭就緒」表示後續資源形狀已可決定。
- 「內容就緒」表示 CPU 工作所需的輸入內容已完整。
- 「資源就緒」表示輸出資源與記憶體額度已準備完成。
- 三項條件同時成立後，工作才具備進入 CPU 任務執行器的資格。

首次讀取時，標頭資訊與其餘檔案內容以非同步工作分成兩條可平行推進的邏輯路徑。標頭路徑推動格式驗證與輸出資源準備，內容路徑取得 CPU 工作所需的完整輸入。兩條路徑的完成條件最後匯合，決定工作何時可以派發：

```text
圖片需求
├─優先取得標頭資訊─▶ 標頭就緒 ─▶ 驗證與準備輸出資源 ─▶ 資源就緒
└─取得其餘檔案內容──────────────────────────────────▶ 內容就緒

標頭就緒 ＋ 內容就緒 ＋ 資源就緒 ─▶ 可派發 CPU 工作
```

儲存介面可以依平台能力選擇請求數量、資料切割、對齊方式與完成通知機制。每種實作都必須保留上述三項完成條件，並維持資源準備與其餘內容讀取的重疊關係。

### 單張圖片的處理時序

```text
主執行緒          儲存任務執行器       CPU 任務執行器       圖形任務執行器
    │                    │                    │                    │
    │─非同步提交讀取────▶│                    │                    │
    │◀─標頭就緒事件──────│                    │                    │
    │─更新資源需求並推進資源準備              │                    │
    │◀─內容就緒事件──────│                    │                    │
    │─非同步派發 CPU 工作────────────────────▶│                    │
    │◀─CPU 工作完成事件───────────────────────│                    │
    │─非同步提交資源傳輸─────────────────────────────────────────▶│
    │◀─資源傳輸完成事件───────────────────────────────────────────│
    │─建立呈現授權並非同步提交繪製───────────────────────────────▶│
    │◀─畫面完成或呈現額度事件─────────────────────────────────────│
```

圖中的垂直順序只表示同一張圖片的資料相依性；箭頭沿用前節定義的非同步交接。具體 API 與資料結構由實作層選擇。

### 主執行緒的控制邊界

主執行緒每次被事件喚醒後，依全域控制狀態處理已就緒事件，產生對應的工作描述或狀態授權；沒有已就緒事件時返回中央事件等待。

中央事件等待是主執行緒唯一可長時間停留的位置。進入等待前必須交回共享同步資源的存取權；等待機制在事件到達前暫停主執行緒的執行。

## 目前實作對應

前章的設計規則是責任與完成條件的依據；本章將目前程式元件對應到各項設計角色與交接契約。

### 關係種類

```text
事件→ 外部輸入或非同步完成通知，經事件分派器送至固定事件處理流程
讀取→ 使用狀態或資料並保持原值
寫入→ 建立或取代狀態或資料
讀寫→ 讀取後修改同一狀態或資源
擁有→ 將狀態、資源生命週期或共享通道統一收納於單一資源擁有者
計算→ 產生本次同步呼叫使用的暫時選擇或順序，並保持持久狀態原值
判斷→ 依已讀取資料選擇控制分支，並保持持久狀態原值
呼叫→ 事件處理流程立即執行事件專用流程或共用流程
命令→ 呼叫固定成本的控制 API，並在同一個控制步驟內返回
派發→ 非同步將 CPU 工作描述放入工作佇列；Worker 完成後產生完成事件
提交→ 非同步將儲存要求或圖形命令交給外部執行資源；完成後產生系統事件
```

事件參數攜帶事件來源資料；接收事件的處理流程從單一資源擁有者讀取其餘判斷所需的狀態與資源。單一資源擁有者保存事件處理流程與共用流程使用的全部可變狀態。

### 狀態與資源所有權

事件所需資源高度耦合，且全部由同一主執行緒依明確順序修改，因此所有狀態、資源生命週期與共享通道統一收納在一個資源擁有者。每個事件處理流程與共用流程都存取這個擁有者；資源擁有者將工作專屬資源實例授予 Worker 與非同步系統服務執行工作。

### 共用流程

圖中未加前綴的狀態與資源都位於同一個 `資源上下文` 內。

#### 重新計算緩衝需求

```text
[共用流程] 重新計算緩衝需求
│
├─讀取→ 圖片索引範圍
├─讀取→ 按住方向
├─讀取→ 最後有效導航方向
├─讀取→ 待完成短按承諾
├─讀取→ 長按 repeat 暫定終點
├─讀取→ 目前呈現索引
│
├─寫入→ 必須依序呈現範圍
├─寫入→ 解碼預取範圍
```

輸入狀態、索引邊界及目前呈現位置決定導航授權與緩衝範圍；解碼結果決定圖片進入後續管線的時機。

#### 回收範圍外工作與 slots

```text
[共用流程] 回收範圍外工作與 slots
│
├─讀取→ 必須依序呈現範圍
├─讀取→ 解碼預取範圍
├─讀取→ GPU 預取範圍
├─讀寫→ 每張圖片的需求狀態與關聯 Slot ID
├─讀寫→ 工作佇列的生產端與工作取消旗標
├─讀寫→ 壓縮 PNG slot 狀態與可分配索引
├─讀寫→ 解碼 staging texture slot 狀態與可分配索引
├─讀寫→ GPU texture slot 狀態與可分配索引
├─讀寫→ 可呈現 GPU 圖片索引
├─讀寫→ staging 與 GPU 記憶體使用量
│
├─判斷→ 已要求且尚未取得 slot 的索引離開需求範圍
│   └─寫入→ 需求狀態為範圍外
├─判斷→ 壓縮 slot 正在接收檔案資料且索引已離開需求範圍
│   ├─寫入→ 壓縮 slot 為等待目前工作結束後回收
│   └─命令→ CancelIoEx
├─判斷→ 仍在工作佇列且索引已離開需求範圍
│   └─寫入→ 以工作項目的原子旗標取消；只有尚未被 Worker 取得時立即釋放資源
├─判斷→ Worker 已取出且索引已離開需求範圍
│   └─寫入→ 完成後可直接釋放
├─判斷→ 解碼 staging texture 位於保留範圍外且未被 Worker 或 GPU 使用
│   └─寫入→ staging slot 為可分配並加入可分配索引
└─判斷→ 可呈現 GPU 圖片位於保留範圍外且索引與目前畫面相異
    ├─寫入→ 從可呈現 GPU 圖片索引移除圖片
    └─寫入→ 對應 GPU texture slot 等待先前繪製完成後設為可分配並加入可分配索引
```

固定資源儲存區在整個工作階段持續擁有實體資源；回收時解除圖片與 Slot ID 的關聯並更新 slot 狀態。可分配索引專門提供可用 Slot ID；分配後的工作提交、完成處理與狀態轉換都直接攜帶 Slot ID。呈現時透過可呈現 GPU 圖片索引直接取得 GPU texture Slot ID。

#### 批次提交可執行的檔案讀取

```text
[共用流程] 批次提交可執行的檔案讀取
│
├─讀取→ 必須依序呈現範圍
├─讀取→ 解碼預取範圍
├─讀取→ 圖片路徑表
├─讀取→ 每張圖片的需求狀態與關聯 Slot ID
├─讀寫→ 壓縮 PNG slot 狀態與可分配索引
├─讀取→ 壓縮資料記憶體使用量
├─讀取→ 預估解碼輸出保留額度
├─讀取→ staging 記憶體額度
│
├─計算→ 範圍內已要求且尚未關聯任何 slot 的圖片
├─計算→ 必須呈現的相鄰圖片優先，其次才是預取圖片
├─判斷→ 對每個目前可容納的圖片
│   ├─寫入→ 取得可分配的壓縮 slot 並設為正在接收檔案資料
│   ├─寫入→ 保留預估解碼輸出額度
│   ├─寫入→ 圖片關聯壓縮 Slot ID
│   ├─判斷→ 標頭資訊狀態
│   │   ├─尚未取得 ─▶ 建立「標頭就緒」與「內容就緒」兩條邏輯路徑
│   │   └─已快取 ───▶ 直接沿用標頭資訊並建立「內容就緒」路徑
│   └─提交→ 符合標頭優先原則的 Windows 非同步檔案 I/O 工作描述
└─判斷→ 待讀需求已全部提交，或下一筆會超過記憶體或 slot 數量上限時結束
```

一般事件一次提交全部已取得 compressed reservation 且目前可執行的讀取；提交集合只由需求範圍、記憶體上限與壓縮 slot 數量上限共同決定。每張圖片的讀取工作描述必須遵守 [標頭優先的資源準備原則](#標頭優先的資源準備原則)。一般資料夾冷啟動在暫時 catalog 只有首圖，因此先提交首圖；目錄 I/O 完成並建立完整 reservation 後，同一次共用流程會派發所有能取得 compressed slot 與記憶體額度的 reservation。固定驗證清單也遵守相同規則。Direct3D、Direct2D、swap chain 與 back buffer 各初始化階段之間，已完成的 I/O 會先填充工作佇列，讓解碼與剩餘圖形初始化重疊；其餘初始化階段直接依序繼續。任何釋放 slot 或記憶體額度的事件都會再次呼叫本流程。

```text
│
├─讀寫→ 工作佇列的消費端與工作取消旗標
├─讀取→ 工作描述指定的輸入資源 Slot ID
├─計算→ 工作描述指定的 CPU 密集階段
├─寫入→ 工作描述指定的輸出資源 Slot ID
├─讀寫→ 完成佇列的生產端
└─事件→ Worker 工作完成 [主事件迴圈]
```

目前工作佇列中的工作描述是 PNG 解碼：輸入為 Windows 非同步檔案 I/O 填入的壓縮 PNG slot，輸出為已映射的解碼 staging texture slot。所有 Workers 從同一條工作佇列領取工作。

```text
[外部非同步執行器] Windows 非同步檔案 I/O
│
├─讀取→ `批次提交可執行的檔案讀取` 建立的檔案範圍、長度與目的緩衝區
├─寫入→ 壓縮 PNG slot 中對應的檔案內容範圍
├─事件→ 首次讀取的標頭資訊就緒 [主事件迴圈]
└─事件→ 完整內容就緒 [主事件迴圈]
```

目前 Windows 儲存介面的對應方式如下：

| 條件 | 目前機制 |
| --- | --- |
| Windows 11 | I/O Ring 與註冊緩衝區讀取描述 |
| Windows 10 | IOCP 與重疊式讀取要求 |
| 首次讀取 | 優先讀取足以決定 PNG 輸出資源的標頭範圍，並同時讀取其餘內容 |
| 標頭資訊已保存 | 沿用既有標頭資訊並提交完整內容讀取 |

首次讀取的標頭範圍至少涵蓋目前 PNG 解析器判斷輸出資源所需的 24 位元組，並依底層儲存介面的 I/O 對齊單位向上對齊。分割後的檔案範圍完整覆蓋本次內容且彼此互斥。這些數值與 API 屬於目前 Windows／PNG 配接層；設計層的要求是「標頭就緒、內容就緒、資源就緒」三項完成條件及其重疊關係。

```text
[外部非同步執行器] GPU 命令佇列
│
├─讀取→ GPU 上傳工作指定的解碼 staging texture slot
├─寫入→ GPU 正在寫入的 GPU texture slot
└─事件→ GPU 上傳完成 [主事件迴圈]
```

```text
[外部事件來源] DXGI SwapChain
│
└─事件→ Frame 提交額度可用 [主事件迴圈]
```

工作佇列與完成佇列是主執行緒和 Workers 之間的共享通道。工作項目的原子旗標協調「等待領取、已由 Worker 取得、已取消」；完成佇列由多個 Worker 寫入，主執行緒依完成事件讀取結果。工作只攜帶工作種類與 Slot ID；固定資源儲存區保持資源位址與所有權穩定，slot 狀態授權單一 Worker 在 CPU 密集工作期間讀寫指定資源。
